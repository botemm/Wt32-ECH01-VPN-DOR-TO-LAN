# Очікувані зміни наступної версії: одна прошивка для WT32 і ESP32

## Універсальний образ

Збирати **один і той самий файл прошивки** для WT32-ETH01 з Ethernet-чипом LAN8720 і звичайної ESP32 без Ethernet-чипа (зокрема тестової ESP32 D1 mini). Не вимагати від користувача окремої збірки або вибору образу для роботи через Wi-Fi.

- Під час запуску визначати доступність Ethernet. Якщо LAN8720 відсутній або його ініціалізація не вдалася, записати зрозуміле повідомлення в журнал і продовжити запуск через Wi-Fi. Відсутність Ethernet не повинна спричиняти `abort()` чи цикл перезавантажень.
- На WT32 з робочим Ethernet зберегти Ethernet, Wi-Fi та автоматичний вибір доступного підключення. На ESP32 без Ethernet приховати або позначити Ethernet як недоступний; налаштування Wi-Fi, точка доступу, вебпанель і WireGuard повинні працювати без нього.
- Коректно обробляти відсутній Ethernet-інтерфейс у статусі, виборі маршруту, скануванні мережі й інших частинах програми. Не припускати, що вказівник Ethernet-інтерфейсу завжди існує.
- Врахувати відмінності GPIO плат. Ініціалізація LAN8720 та керування його живленням не мають заважати звичайній ESP32 або підключеній до неї периферії. Якщо безпечне автоматичне визначення неможливе для певної плати, передбачити зрозумілий вибір апаратного профілю в налаштуваннях, але залишити **один образ прошивки**.
- Пояснити в інтерфейсі та документації, що режим без Ethernet використовує Wi-Fi як підключення до локальної мережі, а доступ через тунель обмежений тією мережею, до якої ESP32 фактично підключена.

## Критерії перевірки

1. Записати той самий factory-образ на WT32-ETH01 та ESP32 D1 mini. Обидві плати запускаються без перезавантажень; вебпанель доступна через точку налаштування.
2. На ESP32 без PHY серійний журнал повідомляє, що Ethernet недоступний, але Wi-Fi підключається до роутера; статус, визначення підмережі та сканування працюють через Wi-Fi.
3. На WT32 Ethernet працює як раніше, а перехід на Wi-Fi при його недоступності не порушує роботу панелі та тунелю.
4. Перевірити WireGuard handshake і доступ клієнта тунелю до пристрою в локальній мережі окремо для WT32 через Ethernet і ESP32 через Wi-Fi.

Поточний тест на COM69 показав причину цієї вимоги: ESP32 D1 mini починає транслювати точку доступу, але ініціалізація відсутнього LAN8720 завершується помилкою `wrong chip OUI`, після чого `ESP_ERROR_CHECK(esp_eth_driver_install(...))` викликає `abort()` і плата перезавантажується. Цей файл описує майбутню зміну; поточну прошивку він не змінює.
