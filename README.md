# Wt32-ECH01-VPN-DOR-TO-LAN

### Доступ до локальної мережі через WireGuard за допомогою WT32-ETH01

Підключіть невелику плату WT32-ETH01 до домашньої, офісної або віддаленої мережі — кабелем чи через Wi-Fi. Вона встановить тунель до **вашого WireGuard-сервера**, а інші клієнти цього сервера зможуть звертатися до пристроїв у мережі WT32: камер, NAS, контролерів, принтерів і вебпанелей. На кожен із цих пристроїв не потрібно встановлювати VPN.

> [!NOTE]
> Назва репозиторію збережена як **Wt32-ECH01-VPN-DOR-TO-LAN**. Назва самої плати — **WT32-ETH01**. Поточна прошивка призначена саме для неї; звичайна ESP32 без Ethernet-чипа [поки не підтримується](NEXT-VERSION-CHANGES.md).

![Демонстраційний вигляд україномовної вебпанелі](docs/interface-preview.png)

## Як це працює

```text
Телефон або ноутбук ── WireGuard ── VPN-сервер ── WireGuard ── WT32-ETH01
                                                                  │
                                                        Ethernet або Wi-Fi
                                                                  │
                                               Камери · NAS · контролери · ПК
```

WT32 працює як **шлюз із IPv4 NAT**. VPN-клієнт надсилає пакет до локальної адреси, наприклад `192.168.10.100`; WT32 передає його в підключену мережу від своєї локальної адреси й повертає відповідь через тунель. Тому на камері або NAS не потрібно змінювати шлюз чи додавати статичний маршрут.

Це зручно, коли потрібно:

- переглядати камери або відкривати вебінтерфейс NAS із-за меж дому;
- обслуговувати обладнання на віддаленому об’єкті;
- дістатися до пристроїв, які не підтримують WireGuard;
- отримати доступ до мережі без публічної IP-адреси: достатньо, щоб WT32 могла підключитися **назовні** до вашого VPN-сервера.

Прошивка **не створює VPN-сервер**. Потрібен власний сервер WireGuard, на якому можна налаштувати маршрути та пересилання пакетів між клієнтами.

## Можливості

| | |
| --- | --- |
| **Підключення** | Ethernet, Wi-Fi 2,4 ГГц або автоматичний вибір: кабель має пріоритет, Wi-Fi підхоплює з’єднання після його втрати. |
| **Тунель** | Один WireGuard-тунель до вашого сервера; повторне підключення після зміни мережі. |
| **Доступ до пристроїв** | IPv4 NAT із тунелю до безпосередньо підключеної локальної підмережі. |
| **Налаштування** | Адаптивна україномовна вебпанель: підключення, підмережа, рекомендації для сервера й клієнтів, імпорт `.conf`. |
| **Інструменти** | Пошук IP- і MAC-адрес пристроїв у поточній локальній мережі до /24. |
| **Точка налаштування** | Окремі назва та пароль; автоматичне вимкнення після заданого часу без підключених клієнтів. |

> [!IMPORTANT]
> Версію **1.1.0** зібрано й записано на WT32; запуск нової вебпанелі підтверджено. Наскрізну роботу Ethernet, тунелю та доступу до пристроїв LAN ще потрібно перевірити на обладнанні. Подробиці — у [звіті](BUILD-REPORT.md) і [плані апаратної перевірки](tests/HARDWARE.md).

## Встановлення

Потрібні **WT32-ETH01 з ESP32, LAN8720 і флешпам’яттю 4 МБ**, адаптер USB–UART із логічними рівнями **3,3 В** та Python з пакетом `esptool`. Для входу в режим прошивання з’єднайте GPIO0 із GND і перезапустіть плату. З’єднання UART: TX↔RX та спільна земля; забезпечте стабільне живлення.

Завантажте готовий образ із каталогу [`release`](release). Виберіть **одну** з команд:

| Ситуація | Файл | Адреса запису | Налаштування |
| --- | --- | --- | --- |
| Перше встановлення або повне скидання | [`wt32-link-factory.bin`](release/wt32-link-factory.bin) | `0x0` | Скидаються |
| Оновлення встановленої WT32 Link | [`firmware.bin`](release/firmware.bin) | `0x10000` | Зберігаються |

```powershell
# Перше встановлення
python -m esptool --chip esp32 --port COM5 --baud 460800 write_flash 0x0 release/wt32-link-factory.bin

# Оновлення зі збереженням налаштувань
python -m esptool --chip esp32 --port COM5 --baud 460800 write_flash 0x10000 release/firmware.bin
```

Команди запускайте з кореня проєкту; `COM5` замініть на порт свого адаптера. **Не записуйте `firmware.bin` за адресою `0x0`.** Після запису від’єднайте GPIO0 від GND і знову перезапустіть плату. Інші варіанти запису наведені у [`release/FLASH.txt`](release/FLASH.txt), контрольні суми — у [`release/SHA256SUMS.txt`](release/SHA256SUMS.txt).

### Перше підключення

1. Знайдіть точку доступу `WT32-Link-XXXXXX` і підключіться до неї. При **першому встановленні** пароль — `12345678`.
2. Відкрийте [http://192.168.4.1](http://192.168.4.1). Початкові дані входу до панелі: `admin` / `12345678`. Якщо WT32 підключена до роутера, панель також доступна за IP-адресою, яку видав DHCP.
3. Після входу змініть паролі адміністратора й точки доступу. Це **окремі** налаштування в розділі «Доступ до пристрою і точка налаштування».

Після **оновлення** прошивки старі логін, паролі та параметри WireGuard зберігаються. Значення `12345678` застосовуються лише під час чистого встановлення. Початково точка доступу вимикається через 300 секунд без клієнтів і знову з’являється після перезапуску WT32; час можна змінити в панелі.

## Налаштування доступу до LAN

Вебпанель веде через чотири кроки:

1. **Підключіть WT32 до мережі.** Виберіть Ethernet, Wi-Fi або автоматичний режим. Можна підготувати наступні кроки ще до фактичного підключення.
2. **Вкажіть підмережу, до якої потрібен доступ.** Наприклад, `192.168.10.0/24`. Якщо WT32 вже підключена, натисніть «Визначити автоматично»; інакше впишіть адресу вручну. Після підключення звірте її з фактичною мережею.
3. **Налаштуйте сервер і клієнтів WireGuard.** Панель запропонує значення `Allowed IPs` та `Endpoint Allowed IPs` для peer WT32 і двох перших клієнтів.
4. **Імпортуйте конфігурацію WT32.** Завантажте її файл `.conf` із сервера або заповніть поля вручну, увімкніть тунель і збережіть. WT32 перезапуститься.

Значення з кроку 2 допомагає скласти рекомендації для сервера. **Пакети WT32 передає до фактично підключеної локальної мережі**, тому після зміни роутера або підмережі маршрути на сервері та клієнтах потрібно перевірити знову.

### Приклад для WGDashboard

Нехай VPN-підмережа — `10.7.0.0/24`, адреса WT32 у тунелі — `10.7.0.2`, локальна мережа за нею — `192.168.10.0/24`, а клієнти мають адреси `10.7.0.3` і `10.7.0.4`.

| Peer на сервері | `Allowed IPs` — маршрути на сервері | `Endpoint Allowed IPs` — маршрути в експортованому конфігу пристрою |
| --- | --- | --- |
| **WT32** | `10.7.0.2/32, 192.168.10.0/24` | `10.7.0.0/24` |
| **Клієнт 1** | `10.7.0.3/32` | `10.7.0.0/24, 192.168.10.0/24` |
| **Клієнт 2** | `10.7.0.4/32` | `10.7.0.0/24, 192.168.10.0/24` |

Для наступного клієнта виділіть нову VPN-адресу `/32` у `Allowed IPs`, а в `Endpoint Allowed IPs` залиште VPN- і LAN-підмережі. **Endpoint на сервері для WT32 зазвичай не потрібен:** вона сама встановлює вихідне з’єднання. Поле `Endpoint Allowed IPs` у WGDashboard має інше призначення — воно потрапляє в конфігурацію пристрою.

На сервері потрібно дозволити **IPv4 forwarding і пересилання між WireGuard peer**, зокрема трафік, що входить і виходить через той самий інтерфейс. Якщо сервер створює маршрути через `wg-quick`, LAN-маршрут зазвичай випливає з `AllowedIPs` peer WT32; при ручному керуванні `wg set` може знадобитися окремий системний маршрут. Не призначайте весь діапазон `10.7.0.0/24` peer WT32 — інші клієнти мають власні адреси.

Перевірка: з віддаленого клієнта зверніться спочатку до `10.7.0.2`, а потім до реального LAN-пристрою, наприклад `http://192.168.10.100`. Якщо пристрій блокує ICMP, перевіряйте потрібний TCP-сервіс, а не лише `ping`.

## Якщо WT32 переїхала в іншу мережу

Якщо нова локальна підмережа відрізняється, оновіть її в `Allowed IPs` peer WT32 **на сервері** та в `Endpoint Allowed IPs` віддалених клієнтів. Уже видані клієнтські конфігурації самі не зміняться — їх потрібно оновити або імпортувати повторно. VPN-адресу WT32 і ключі зазвичай міняти не треба. У панелі WT32 також оновіть вручну записану LAN-підмережу, щоб рекомендації відповідали новій мережі. Подробиці пояснює розкривна підказка біля маршрутизування.

## Межі поточної версії

- Підтримується **IPv4** і одна безпосередньо підключена LAN-підмережа. Це шлюз із NAT, **не прозорий Ethernet-міст**: широкомовне виявлення та mDNS через тунель не передаються.
- LAN, VPN-підмережа, мережа точки налаштування `192.168.4.0/24` і мережа віддаленого клієнта не повинні перетинатися.
- Імпортер `.conf` бере одну IPv4-адресу WT32, попереджає про додатковий LAN-маршрут або IPv6-адресу в `Address` і вимагає перевірити VPN-підмережу. `AllowedIPs = 0.0.0.0/0` не перетворює WT32 на інтернет-шлюз.
- IPv6-трафік, кілька серверних peer, команди `PreUp`/`PostUp` та OTA-оновлення не підтримуються. DNS із `.conf` не застосовується: WT32 використовує DNS підключеної мережі.
- Для запуску тунелю після перезавантаження потрібні DNS, доступ до NTP і UDP-зв’язок із WireGuard-сервером. Поточні TCP-з’єднання можуть обірватися під час перемикання між Ethernet і Wi-Fi.
- Вебпанель працює через локальний **HTTP без шифрування**. Не відкривайте її порт 80 у публічний інтернет. Ключі зберігаються в NVS без flash encryption; API не повертає їх у відкритому вигляді.
- Швидкість і стабільність залежать від ESP32, якості мережі та шифрування; заявленої продуктивності без апаратних вимірювань немає.

## Збірка з вихідного коду

Проєкт використовує **PlatformIO espressif32 6.10.0 та ESP-IDF 5.4**. Звичайна збірка в Arduino IDE не підходить: прошивці потрібні IPv4 forwarding і NAPT у lwIP. Вебпанель вбудована в образ, окремий розділ файлової системи завантажувати не потрібно.

```powershell
pio run
node --test tests/*.test.cjs
```

На Windows, якщо шлях до проєкту містить пробіли або кирилицю, скористайтеся скриптом:

```powershell
./tools/build.ps1 -Python python
```

Він збирає проєкт в ASCII-каталозі `%TEMP%\wt32-link-build` і кладе готові образи до `release`. За браку місця на диску C: задайте інший каталог, наприклад `-StageRoot D:\wt32-link-build`. Потрібен Python із `pip`; перша збірка завантажить інструменти ESP-IDF.

Для перегляду демонстраційної вебпанелі без плати запустіть `python tools/preview.py` і відкрийте `http://127.0.0.1:8765`. Показники там умовні, а збереження вимкнено. Це перевірка інтерфейсу, не перевірка VPN.

Компонент WireGuard розміщений у [`components/wireguard`](components/wireguard); його походження, ліцензія та локальні зміни описані в [`UPSTREAM.md`](components/wireguard/UPSTREAM.md).
