# Перевірка WT32 Link

Дата оновлення: 2026-10-02.

- Успішна збірка для `wt32-eth01`, ESP32, 4 МБ flash.
- Розмір застосунку версії 1.1.0: 930 048 байтів; повний factory-образ: 995 584 байти.
- PlatformIO 6.2.0, платформа espressif32 6.10.0, ESP-IDF 5.4.0,
  Xtensa GCC 14.2.0+20241119, esptool 4.5.1.
- У зібраному SDK увімкнено IPv4 forwarding, NAPT, блокування TCP/IP core,
  окреме зберігання ESP-NETIF metadata, DNS активного інтерфейсу та два NTP-сервери.
- Тринадцять тестів імпорту WireGuard / IPv4 / CIDR / маршрутів і зв’язків
  інтерфейсу пройшли.
- Оновлену вебпанель перевірено в Chrome на десктопному та вузькому екрані.
  Демонстраційні поля й чотири кроки відображаються без переповнення основного
  вмісту; навігація прокручується горизонтально на телефоні.
- Демонстраційний backend використовує явно позначені умовні показники
  і забороняє запис. Наявність зеленого статусу у preview не є тестом VPN.
- Повний factory-образ пакується з перевіркою ESP32 magic, таблиці розділів,
  розмірів та неперетину bootloader / partition table / application.
- Формуються SHA-256 контрольні суми образів та архіву вихідного коду.
- Перевірено ESP32 image checksum і validation hash утилітою esptool;
  у ELF присутні маршрутизатор, WireGuard і обидва напрями NAPT.

**Виконано на фізичній WT32:** образ 1.1.0 записано на ESP32 з MAC
`20:43:a8:ba:e2:d0` через COM3; esptool підтвердив хеш після запису.
У локальній мережі новий маршрут вебпанелі `/api/scan` відповів запитом
авторизації. Це підтверджує запуск нової версії, але не проходження VPN-трафіку.

**Ще не підтверджено для версії 1.1.0:** роботу Ethernet, реальний WireGuard
handshake, прохід TCP/UDP/ICMP через NAT до окремого LAN-пристрою, апаратний
failover, тривалий навантажувальний тест і вимірювання швидкості.
План — `tests/HARDWARE.md`.

Цей звіт стосується образу 1.1.0. Старі експериментальні `.ino`-файли не
входять до опублікованого проєкту.
